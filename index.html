Part one · the harness  ·  what has already changed

Five things that are no longer arguable

“It is already clear that:

  • (i) As AI makes coding easier, a lot more people will be doing it.
  • (ii) Writing code by hand and even reading (generated) code is not that important, because we can ask an LLM about the code and operate at a higher level than the raw syntax (although how high we can or should go is rapidly changing).
  • (iii) There will be a lot more custom applications, because now it's economical to write software for smaller and smaller audiences.
  • (iv) Deciding what to build, more than the actual building, is becoming a bottleneck.
  • (v) The cost of paying down technical debt is decreasing (since AI can refactor for you).”
Andrew Ng — on the future of software engineering, 2026 · x.com/AndrewYNg

What has already changed · the cost

What “more” costs us

If nobody reads the generated code, reading is no longer the safety net. Something else has to be — or there isn't one.

“Human review is being bypassed. When developers accept AI-generated code with minimal or no review, the traditional human safeguard against intent violations disappears. […] The intent gap — the distance between what a user means and what a program does — is the central reliability bottleneck.”

Shuvendu K. Lahiri, Microsoft Research — “Intent Formalization: A Grand Challenge for Reliable Coding in the Age of AI Agents”, Mar 2026 · arXiv:2603.17150

This talk rebuilds that safeguard out of something other than human attention.

What has already changed · the upside

What judgment and cheap refactoring buy us

(iv)  deciding what to build

The spec becomes the scarce artifact — the thing that carries intent rather than machinery. And intent is something a human can review efficiently.

(v)  cheap refactoring

Cheap refactoring makes a complexity budget enforceable. Paying down debt is no longer a year-long project — so we can finally insist the repo stays simple and clean.

What has already changed · slop

Slop looks right. It is the most expensive code we ship.

Plausible-looking. Compiles. Even passes a test or two. Wrong — and the next agent inherits it.

“I think code is not cheap. In fact, bad code is the most expensive it’s ever been. Because if you have a codebase that’s hard to change, you’re not able to take all of the bounty that AI can offer.”

Matt Pocock — “It Ain’t Broke: Why Software Fundamentals Matter More Than Ever”, AI Engineer Europe, Apr 2026 · video · 3:55

Principle 2 · nobody grades their own homework

  
The agent that writes the code cannot be the agent
     that judges it

  
An agent whose job is
     code to green, and that decides whether a surviving mutant or a lint rule may be waived,
     is deciding inside a goal that is biased towards allowing it. A separate,
     read-only agent has no such goal — so it judges honestly. That is the whole of
     “nobody grades their own homework.”

  

    
We had it collapsed

      
Phase 3 wrote the code and triaged its own
         mutation survivors — which is how you get a 100% score that measures nothing.
         The judgment moved out, into a read-only phase 5.

    
The rule

      
A suppression is legitimate only when the
         invariant that makes the mutant equivalent is named and proved — never by what the tests happen
         to do. Every disable is audited: apply the mutant by hand, run the suite, restore.

  






  
Principle 3 · the panel · swiss-cheese review

  
No single gate is bulletproof — so we stack them

  
Every gate has holes. Stack enough of them and the holes stop lining up. Hover a slice.

  
  
Triage every comment: fix it, or reply. Never leave one silently unresolved.

Cost mitigation

  
You're out of quota. Now what?

  
Three moves. Only one of them is expensive.

  

    

      
✗ Keep going 💰💰💰

      
The default — it needs no decision,
         so nobody makes one.

    

    

      
✓ Don't hop — flip 💵

      
One command. Same session, same
         context — swap what's behind it.

    

    

      
✓ Hop, but hand off 💵

      
Burn the seats you already pay for
         first: Claude Code → Cursor → OpenCode / pi. The
         artifacts are the handoff.

    

  

  
Decide
     before you're out — not after.







  
Valar  ·  arm one  ·  the wrapper

  
Valar Code: two commands instead of a tool-hop

valar claude off   # hand back to your seat

      
It re-points the tool you are
         already in. Same repo, same /spec-to-ship, same guardrails.
         Nothing about your workflow changes — which is the entire point.

The plumbing  ·  click a box

  
One gateway, several meters behind it


  

  

    
Click a box

    

      
OpenCode  ·  where you work

      
A coding agent, like Cursor or Claude Code — except it talks to
         any inference provider out of the box, so it is not
         tied to one vendor's models.

    

    

      
LiteLLM  ·  the gateway

      
Acts as our own inference provider. Behind it: other
         providers, proxied — or models we host ourselves.
         We run it centrally, so you don't have to.

    

    

      
Bedrock  ·  behind it, on credits

      
An inference provider — AWS's. What we spend here comes out of
         credits we already hold.

    

    

      
Anthropic  ·  behind it, metered

      
An inference provider — the same models your Claude Code
         seat runs on. Through the gateway they are metered per token,
         no seat required.

    

    

      
Valar  ·  behind it, negotiated

      
An inference provider with cheaper-than-list tiers on
         strong open-weight models. Wait a little, pay a lot less.
         Both arms you just saw live behind this box.

Where to put the effort

  
Cheapen the grind. Never the judgment.

  

    

      
Cheapen freely 💵

      
Phase 3, the grind. High volume,
         mechanical, and a red suite catches it if the cheap model gets it wrong.

    

    

      
Never cheapen

      
Judgment. Spec. Ideation.
         Nothing downstream catches a bad decision — it just gets implemented, faithfully.

    

  

  

    
The policy, in order

    
1. Burn the seat first — it's
       already paid for.  2. When it runs dry, fall through — don't hop.
        3. On the metered path, cheap alias for volume, strong for judgment.

Appendix  ·  the decision ladder

  
Make the agent ask only what it can't infer

  
Otherwise you get
     decision fatigue — and at 6pm you YOLO-click the recommended option a hundred times.
     That is not review.

  

    

      
The ladder, in order

      
    
        
  1. Change nothing observable unless asked.
    2. 
        
  2. Only what was explicitly requested — ticket, thread, doc.
    3. 
        
  3. A behaviour change is forced and nobody addressed it → ask.
    4. 
      

    

    

      
No approval gates ≠ no gates

      
Every technical call — naming,
         decomposition, test structure — is the agent's to make and record. It halts for exactly one
         thing: a behavioural question nothing written down can settle.

    

  

  

    
“A good harness should not necessarily aim
       to fully eliminate human input, but to direct it to where our input is most
       important.” — Birgitta Böckeler
